# UI guide: Rozbirka Web

## Межі та джерело

Опис поточної робочої гілки `feat/remove-free-parts`: HEAD `7ea1280382e12374a8f9e909a04c010ca3b3b466` плюс локальні зміни, досліджені 2026-09-30 і звірені з кодом 2026-10-01. Користувач явно обрав цю версію включно з кабінетом. Це не твердження про merge в main, бізнес-погодження або production. При перенесенні документації на іншу гілку спершу звірити джерела.

Документи пояснюють розподіл відповідальності та вибір реалізації. Значення токенів, props і бізнес-правила не дублюємо: посилання ведуть до коду та чинних контрактів. Перед зміною читати актуальні файли, не покладатися лише на цей snapshot.

## Межі UI

- Лендинг: [site components](../../src/components/site/), [layout](../../src/components/layout/), Visuelt та маркетингова композиція.
- Кабінет і продуктові форми: [app exports](../../src/components/app/index.ts), app/state tokens, компоненти в [cabinet](../../src/cabinet/).
- [ui Button](../../src/components/ui/button.tsx) обслуговує лише dev-прототипи `/screens` і не є кнопкою лендингу чи кабінету; у кабінеті — [app Button](../../src/components/app/button.tsx), на лендингу — `Link` із brand-класами в site components.
- [UX-CONTRACT](../../UX-CONTRACT.md) володіє описаними там interaction contracts; цей guide не переказує їхні бізнес-рішення. [DESIGN.md](../../DESIGN.md) — ідентичність і ключові значення токенів.
- API та generated contracts живуть у [src/api](../../src/api/) і [contracts](../../contracts/). Стилі не визначають permissions, quotas або retry semantics.

## Правило роботи

Знайти відповідний шар → прочитати джерело й аналогічний екран → повторно використати → перевірити сценарій. Наявність патерну в одному екрані не робить його універсальним. Суперечність із погодженим макетом чи вимогами показати явно; не створювати новий стандарт мовчки.

При зміні спільного UI оновлювати лише відповідний тематичний документ. Деталізацію окремих patterns виносити у нові файли лише за реальної потреби; повний перелік props залишається в TypeScript.
