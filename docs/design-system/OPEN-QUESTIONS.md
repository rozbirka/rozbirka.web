- D46. 9.2/9.4/9.5: касу для післяплати Core показує лише з правом «Налаштування інтеграцій» (`GET shipping/preferences`). Без нього 9.2 — «Нова пошта ще не переказала післяплату. Зазвичай це 1–2 робочі дні.» без назви каси, а `CashRegisterRequired` / `PermissionRequired` — «Не вдалося автоматично зарахувати післяплату. Внесіть оплату вручну в активну касу.» без причини. 9.5 «каса … архівована» — лише коли обрана каса неактивна.
- D47. 9.6: суми виплати Нової пошти Core у ТТН не віддає, тож текст — «Нова пошта повідомила про переказ, що не збігається із залишком {залишок}. Не позначаємо як оплачене, доки ви не звірите суму у «Фінансах».» «Звірити у «Фінансах»» веде в модуль «Фінанси» (`/cash`).
- D48. 9.8: шторка «Внести оплату» — наявна (каси списком, комісія, «Прив’язати операцію»); після отримання посилки вона записує вид `cod`, під заголовком — «Замовлення #N · післяплата за ТТН …», у футері — «Операція з’явиться у «Фінансах»», кнопка — «Внести {сума}». Полів «Дата» й «Спосіб» немає: дату ставить Core, спосіб визначає стан замовлення. Без права «Фінанси» блок «Оплата» без кнопок з підказкою «Вносити оплату й повертати кошти може користувач із правом «Фінанси».»
- D49. 10.1/10.15: «Ще» у шапці показується лише коли в меню є дія — для відправленого, ще не отриманого замовлення там «Почати повернення» (Core приймає `return-start` для будь-якого відправленого замовлення). До відправлення в шапці — «Скасувати замовлення» з діалогом наслідків (у макеті діалогу немає): «Скасувати замовлення?», «Замовлення #N буде скасовано, резерв товарів знято.», «Спершу скасуємо ТТН … у Новій пошті.», «Внесені {сума} потрібно буде повернути клієнту — це окремий крок.», «Скасоване замовлення не можна відновити.» Core сам скасовує ТТН у `POST delivery/cancel`.
- D50. 10.3/10.4: «ТТН повернення» — перший номер із `relatedNumbers` ТТН; без нього — «Чекаємо посилку.»; дати прибуття повернення Core не дає. У «Складі повернення» — назва деталі без артикула (у рядку замовлення його немає); відсутню позицію позначають, знявши позначку. «Стан товару»: «Без пошкоджень» / «Є пошкодження» (для другого Core вимагає нотатку — «Опишіть пошкодження.»).
- D51. 10.7–10.10: Core повертає всі неповернені оплати однією операцією, суми не приймає. Поле «Сума» лишається, але менша сума — помилка «Rozbirka фіксує лише повне повернення — {сума}.» «Прив’язати наявну»: каса + пошук «Номер або сума операції» серед видатків каси; номера іншого замовлення Core не повертає — «Операцію вже прив’язано до іншого замовлення.» 10.10 («Повернено частково») можливий лише коли частину оплат повернули раніше окремо.
- D52. 10.13–10.14: стан «ТТН скасовано, замовлення ще ні» Core не зберігає; після «Перевірити результат» зі скасованою ТТН картка «Скасування замовлення» пропонує «Скасувати замовлення» ще раз з текстом «ТТН скасовано. Завершіть скасування замовлення.» Номер скасованої ТТН у кроці видно до перезавантаження (D34); без нього — «Скасувати ТТН».
- D53. 10.16: шторки в макеті немає. «Зафіксувати надходження» / «Прив’язати операцію» відкривають одну шторку з перемикачем «Створити операцію» / «Прив’язати наявну»: «Сума виплати» (за замовчуванням — післяплата ТТН), «Комісія», «Каса» (або надходження каси), «Підстава звірки» — обов’язкова, коли сума чи комісія відрізняється або була ручна звірка (правило Core). Дати надходження Core не дає — «Сплачено» підписано «післяплата · після скасування». Після запису кошти треба повернути: «Повернути кошти» в блоці «Оплата».
