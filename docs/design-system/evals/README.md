# Eval-набір: 5 типових задач

Кожна задача має бриф, еталонну відповідь (файл пакета, з яким порівнюємо) і критерії оцінювання. Оцінка проходить, якщо виконано всі пункти «обовʼязково».

## E1. Список автомобілів з усіма станами
**Бриф:** «Зроби екран списку автомобілів з пошуком, фільтром стану, порожнім станом і помилкою».
**Еталон:** `v2/features/List.dc.html?screen=cars` + `screens/cars.json`.
**Обовʼязково:**
- shell: sidebar з активним «Автомобілі», topbar з breadcrumb «Склад › Автомобілі»;
- 7 станів відкриваються через `?state=`;
- заголовок «Автомобілі», порожній стан «Автомобілів поки немає» і дія «Додати автомобіль» — з `cars/messages.ts`;
- VIN і код — mono, числа праворуч;
- `visual_check.py lint` — 0 проблем.

## E2. Ліміт тарифу на списку деталей
**Бриф:** «Покажи, що бачить користувач, коли вичерпав ліміт деталей».
**Еталон:** `Parts List.dc.html?state=quota`.
**Обовʼязково:**
- «Додати деталь» вимкнена, має іконку замка й `title="Ліміт деталей вичерпано."`;
- Notice warn з текстом `quotaBody` і дією «Порівняти тарифи»;
- список лишається доступним для перегляду;
- це окремий стан, а не DeniedState.

## E3. Підтвердження видалення з конфліктом
**Бриф:** «Діалог видалення деталі, яка вже стоїть у замовленні».
**Еталон:** `Part Detail.dc.html?state=conflict`.
**Обовʼязково:**
- `.rz-confirm`, заголовок «Видалити деталь?» і текст `deleteConsequence` дослівно;
- фокус на «Скасувати»; кнопка danger «Видалити деталь» (без «Ви впевнені?»);
- помилка «Не вдалося видалити деталь через конфлікт.» усередині діалогу.

## E4. Сканер: код не знайдено
**Бриф:** «Екран складського сканера, коли код не належить розбірці».
**Еталон:** `v2/components/Scanner.dc.html` (кадр not found).
**Обовʼязково:**
- 375px; головна дія glove 56px внизу — «Сканувати ще раз»; другорядна — «Ввести код вручну»;
- рамка камери danger; `role="alert"`;
- тексти `notFoundTitle` / `notFoundHint` з `scanners/messages.ts`;
- немає sidebar і ⌘K.

## E5. Світла тема й comfortable-щільність для замовлення
**Бриф:** «Покажи деталі замовлення у світлій темі для бухгалтера».
**Еталон:** `Record.dc.html?screen=order` з `data-theme="light" data-density="comfortable"`.
**Обовʼязково:**
- жодного hex у розмітці, лише `--rz-*`;
- контраст тексту ≥4.5:1 (`--rz-text-dim` #756d66 на білому — 4.9:1);
- суми mono, праворуч;
- «Друк» відкриває стан `printoff`: «Друку замовлення поки немає: сервіс не формує документ.» Документ на друк не вигадувати.

## Як прогнати
1. Дати агенту бриф і `skill/SKILL.md`.
2. `python check/visual_check.py lint <результат>`.
3. Зняти скріншоти результату й еталона (`shoot`), порівняти візуально або через `diff`.
4. Пройти чек-лист «обовʼязково» вручну.
