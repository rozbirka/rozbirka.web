# Розбіжності макетів і застосунку

Журнал переносу макетів Claude Design у кабінет. Для кожного екрана —
що з логіки макета застосунок уже вміє, а чого не вміє й чому.

Поповнюється по одному екрану, у порядку артефактів.

---

## 1. Додати деталь у приймання — `/intakes/:intakeId/parts/new`

Артефакт: `6344180d-ec27-454b-996a-19d0be38e57e`
Реалізовано: так, UI за макетом.

### Працює по-справжньому

| Елемент макета                                             | Як зроблено                                                                                     |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Назва, тип деталі, нотатки, фото                           | `POST /intakes/{id}/parts`                                                                      |
| Стан чипами (б/в · після ремонту · нова · під відновлення) | ті самі чипи, значення мапляться в серверний enum `good / refurbished / new / scrap`            |
| Кількість кнопками − / +                                   | новий примітив `QuantityStepper`, число й далі можна ввести з клавіатури                        |
| Комірка                                                    | `inventoryZoneIds` у тому ж запиті; список комірок — `GET /inventory/zones?activeOnly=true`     |
| Собівартість на одиницю                                    | рахується з приймання: `totalCost / partsCount`                                                 |
| Ціна продажу                                               | приймання її не приймає, тому одразу після створення йде `PUT /parts/{id}` з `desiredSalePrice` |
| Маржа                                                      | `(ціна − собівартість) / ціна`, кольори як у макеті: ≥30% зелений, >0 бурштиновий, ≤0 червоний  |
| «Зберегти й додати ще»                                     | форма лишається відкритою, поля скидаються, лічильник позицій приймання зростає                 |
| «Додані щойно»                                             | список того, що додано в цьому сеансі, з коміркою й кількістю                                   |

### Чого застосунок не вміє

1. **OEM-код.** Поле є в макеті, але його немає ні в `AddPartToIntakeRequest`,
   ні в `UpdatePartRequest`. Зараз поле показане неактивним із підказкою, що
   код вписують на картці деталі. **Треба бекенд:** `oemCode` у запиті
   додавання деталі в приймання (він уже є в самій сутності `Part`).
2. **Собівартість у гривнях.** Макет показує `127,5 $` і `5 228 ₴` з курсом
   41, зашитим у канву. У системі немає ні курсу, ні поля валюти приймання —
   показую лише долари. **Треба рішення:** звідки брати курс (ручне поле в
   налаштуваннях розбірки чи довідник НБУ) і чи потрібна гривня взагалі.
3. **Сканувати комірку.** Кнопка є, камера до форми не підключена — у нас
   сканер живе окремим екраном `/scan`. Кнопка неактивна з поясненням.
   **Треба фронт:** зчитування QR комірки без виходу з форми.
4. **Підказані комірки** (`A-01-04`, `A-01-05` …). У макеті це чотири
   зашиті значення. Замінив на справжній список зон із сервера — фільтра
   «найближчі до цього приймання» немає, бо приймання не привʼязане до зони.
5. **Контекст приймання в шапці** — макет показує «Ангар · зона». Приймання
   в нас не має ні складу, ні зони, тому лишив назву приймання й кількість
   позицій. **Треба бекенд:** привʼязка приймання до складу, якщо це потрібно.

## 2. Редагування запчастини — `/parts/:partId/edit`

Артефакт: `470f2d21-83e7-4980-a0fd-6d12cf056999`
Реалізовано: так, UI за макетом.

### Працює по-справжньому

| Елемент макета                                                       | Як зроблено                                                                                             |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Липка шапка з «Скасувати» / «Зберегти зміни»                         | кнопка в шапці сабмітить форму через `form="part-edit"`                                                 |
| Картка «Джерело», лише для читання, з переходом на авто чи приймання | `PartDetail.carId / carCode / intakeId`; посилання під правами на модуль                                |
| «Опис деталі»: назва, тип, стан чипами, нотатки                      | `PUT /parts/{id}`                                                                                       |
| «Кількість і ціна»: кількість кроками, одиниця, бажана ціна          | той самий запит, ціна через `desiredSalePrice`                                                          |
| «Сумісність» лише для читання                                        | `compatCarBrand / compatCarModel / compatCarYear` у сітці `SpecGrid`                                    |
| Фото                                                                 | наявний завантажувач із чергою й повторами                                                              |
| «Зведення»: доступно, у резерві, QR-код                              | з деталі                                                                                                |
| «Надрукувати стікер»                                                 | веде на `/stickers?part=<id>`; екран стікерів тепер приймає цей параметр і ставить деталь у чергу друку |
| «Видалити запчастину» з поясненням                                   | `DELETE /parts/{id}`; текст залежить від того, чи є резерв                                              |

### Чого застосунок не вміє

1. **OEM-код** — те саме, що й у макеті №1: поля немає в `UpdatePartRequest`,
   тож воно показане неактивним. **Треба бекенд.**
2. **«Зона B · B-04-12» у підзаголовку.** Розміщення деталі лежить в окремому
   модулі (`/parts/{id}/inventory`), у `PartDetail` його немає. Показую QR-код
   і автора створення. **Треба бекенд:** поточна зона в `PartDetailDto`.
3. **«Змінено 15.09.2026 · Олена».** У деталі є лише `createdAt` і
   `createdByName`; хто і коли змінював востаннє — невідомо.
   **Треба бекенд:** `updatedAt` + `updatedByName`.
