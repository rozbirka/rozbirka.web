# Повний флоу перевірки стікерів після уніфікації файлів

Гілка: `codex/storage-sticker-queue`, база цієї зміни `e6e8bb6` з актуалізацією від `rozbirka-pr/develop`. Зміни стосуються спільних дій PDF/HTML/поширення та нейтрального опису екрана; переходи, друковані шаблони й API залишаються чинними. Браузерні й фізичні перевірки виконує користувач.

## Підготовка

1. Оновити локальний веб на `http://localhost:5173` і відкрити «Стікери» у потрібному бізнесі. Використовувати один hostname у межах авторизованої сесії.
2. Для запчастин потрібні `parts.view` + `stickers.manage`, для місць зберігання — `inventory.view`. Мати 25 доступних копій стікерів деталей та склад із понад 25 активними місцями: зонами, секціями й полицями. Тестувати на відповідних тестових даних.
3. Дозволити popup для PDF/друку. Для поширення потрібен браузер, що підтримує передавання файлів через системне меню. Якщо підтримки немає, очікується стандартне toast-пояснення.

## 1. Спільний екран

1. Відкрити «Запчастини», потім «Місця зберігання».
2. В обох режимах заголовок «Стікери» та опис: «QR-стікери для запчастин і місць зберігання. Оберіть потрібні та підготуйте до друку.» Розташування заголовка, опису й перемикача не змінюється.
3. Без вибору й без черги немає дій з порожніми файлами. Пошук, вибір і сторінки по 10 рядків працюють як раніше.

## 2. Файли з вибору без створення черги

Повторити весь блок в обох режимах.

1. Для запчастин вибрати, наприклад, 3 копії однієї та 2 копії іншої деталі; для місць зберігання — 5 конкретних зон/секцій/полиць. Права, доступні залишки та початкові вибори залишаються чинними.
2. У прев'ю підпис «Вибрані стікери · 5» та однакові кнопки: `PDF · 5`, «Завантажити», «Поділитися».
3. Натиснути PDF: відкрилося браузерне вікно друку із 5 стікерами. Обрати «Зберегти як PDF». У PDF кожен стікер на окремому аркуші 40×58 мм; назви, QR і шляхи відповідають вибору.
4. «Завантажити» зберігає `rozbirka-stickers.html`, це HTML-макет для друку. Відкрити файл і перевірити ті самі 5 стікерів, включно з потрібною кількістю копій запчастини.
5. «Поділитися» відкриває системне передавання того самого HTML-файлу. За відсутності підтримки з'являється зрозумілий toast. Немає імітації успіху.
6. Після кожної дії вибір збережений, активна черга не створена, підтвердження друку не з'являється. Немає автоматичного зменшення кількості.
7. Повторити з 25 стікерами: файли містять усі 25 вибраних, а не лише перші 20. Межа вибору для файлу — 200; понад ліміт дії недоступні з поясненням.

## 3. Файли з активної черги

Повторити в обох режимах.

1. Вибрати 25 стікерів → «Підготувати 25». З'являється черга `0 з 25`, вибір очищується.
2. У прев'ю підпис «Наступна партія черги · 20», кнопка `PDF · 20` та ті самі завантаження й поширення. Кнопка `PDF наступних 20` на картці черги працює з тією самою партією.
3. Через усі три дії отримати файли. Кожен містить рівно наступні 20 копій/місць у порядку черги. Повторні копії однієї запчастини не зливаються в одну.
4. Прогрес незмінний: `0 з 25`, у залишку 25; жодна файлова дія не підтверджує друк. Оновлення сторінки відновлює той самий залишок.
5. Надрукувати наступні 20 → «Частково» → підтвердити 7 довільних. Очікування: `7 з 25 надруковано · 18 залишилось`.
6. Усі файли тепер містять наступні 18, прогрес після експорту лишається `7/25`. Перезавантаження зберігає залишок 18.

## 4. Новий вибір за активної черги

1. За наявності черги вибрати ще 2 стікери. У прев'ю змінюється підпис на «Вибрані стікери · 2».
2. PDF/HTML/поширення містять ці 2 вибрані стікери, а не стару партію черги. Черга й новий вибір не змінюються; копії не додаються до черги автоматично.
3. Натиснути «Зняти»: прев'ю та файлові дії знову стосуються наступної партії черги.
4. Надрукувати партію, але поки не підтверджувати. Завантажити або поширити файл: наявне підтвердження попереднього фізичного друку не зникає. Сама файлова дія нового підтвердження не створює.

## 5. Переходи, завершення й незалежність

1. Із картки/списку/приймання запчастин перейти до стікерів: чинний `?part=` додає правильні деталі до вибору, без друку та без неявного створення черги.
2. Склад → «Друк стікерів зон»: виділені лише його зони. Зона → «Друк стікерів секцій»: її секції. Секція → «Друк стікерів полиць»: її полиці; одразу відкрита сторінка першого потрібного місця.
3. Пошук, ручне перегортання й зняття вибору не запускають повторного автоматичного виділення. У файлах лише явно вибране.
4. Перемикати режими: черги запчастин і місць зберігання не змішуються й не скидають одна одну.
5. Для решти 18 підтвердити всі: черга завершується, з'являється стандартний toast «Чергу надруковано.» без банера. Завершена черга не повертається після перезавантаження.
6. Перевірити додавання в кінець, прибирання окремих копій і скасування з підтвердженням. Прибирання не рахується друком.

## 6. Помилки, права й мови

1. Заборонити popup та натиснути PDF: стандартний toast, вибір і черга збережені. Дозволити popup й повторити — дія працює.
2. Поширення не підтримується: стандартний toast, жодного зменшення залишку. Інші файлові дії лишаються доступними.
3. Зробити один потрібний елемент недоступним у тестовому середовищі: немає мовчазного пропуску, весь файл не видається, вибір/черга збережені.
4. Змінити бізнес або вийти під час підготування файлу: старий файл не завантажується, не передається й не відкривається для друку після втрати власника. За зміни активної черги іншою вкладкою застарілий файл партії також не видається.
5. Без права друку відповідні дії недоступні; після втрати права під час асинхронної дії файл не передається.
6. Повторити основний флоу на uk/en-GB/pl, у світлій/темній темах та на вузькому екрані: однакові дії й опис, без обрізаних кнопок та горизонтального overflow.
7. Надрукувати фізичні тестові стікери та відсканувати по одному кожного типу. Перевірити правильну запчастину/місце зберігання. Шаблон QR і друковане компонування не змінювалися цією задачею.

## Виконана автоматична перевірка

На базі `e6e8bb6` із цією реалізацією: `npm run check` PASS (2383 unit + 271 contract + 50 integration = 2704 тестів), `npm run build:qa` PASS. Цільовий набір стікерів: 124 тести. Перевірено вибір 25 без черги, наступну партію 20, збереження прогресу й наявного підтвердження друку, помилку непідтримуваного поширення, очищення blob URL навіть при помилці та відмову від видачі файлу після скидання власника. Локальний Vite віддає спільний `StickerFileActions`.

Браузер, системне меню поширення, реальні PDF-файли, фізичний принтер і сканування після цієї зміни агентом не перевірялися. Це ручні сценарії вище; unit-тести з перехопленими Browser API не замінюють їх.
