# Перевірка повної черги стікерів запчастин

Гілка: `codex/storage-sticker-queue`, актуалізована від `rozbirka-pr/develop` (`004a222`). Core не змінювався: використовуємо чинний `/parts/batch-sticker` та ті самі права. Браузерні й фізичні перевірки виконує користувач.

## Основний флоу

1. Відкрити «Стікери» → «Запчастини». Перевірити чинний перехід також із картки запчастини, списку й приймання: `?part=` відкриває цей режим і додає потрібні деталі до вибору, без друку.
2. Вибрати запчастини й кількість копій. Для сценарію зручно 25 копій однієї деталі з доступними 25 одиницями або кілька деталей із сумою 25. Пошук, пагінація й кількість копій працюють як раніше.
3. «Підготувати 25» створює активну чергу; вибір очищується, друк ще не починається. Є прогрес `0 з 25`, дії наступних 20, редагування й скасування. Прев'ю показує перші 6 копій наступної партії.
4. «Друк наступних 20» відкриває рівно 20 стікерів, включно з повторними копіями однієї деталі. Усі беруть актуальні QR й назви. Друкований формат і посилання сканера не змінені.
5. Після друку обрати «Частково». Позначити 7 довільних копій, у тому числі не підряд; підтвердити. Очікування: `7 з 25 надруковано · 18 залишилось`.
6. Оновити сторінку або перейти в інший розділ і повернутись. Залишається 18 копій тієї самої черги, без повторного додавання підтверджених. Наступний друк містить 18, підтвердження всіх завершує чергу.

## Відмова, PDF та файли

1. Друк → «Нічого не надруковано»: кількість і прогрес незмінні.
2. «PDF наступних N» викликає вікно друку для збереження PDF; після збереження черга не просувається й панель підтвердження не з'являється.
3. «Завантажити» й «Поділитися» створюють HTML тієї самої наступної партії, до 20 копій, без зміни прогресу. Поширення залежить від підтримки браузером.
4. Заблокувати popup: з'являється пояснення; черга збережена, нічого не підтверджено.
5. Зробити одну деталь наступної партії недоступною в тестовому середовищі. Жодного мовчазного пропуску: друк усієї партії зупиняється, прогрес незмінний. Недоступні копії можна прибрати через редактор черги.

## Зміна черги й межі

1. За активної черги вибрати ще деталь і кількість → «Додати до черги · N». Додаються копії в кінець зі збереженням ID і прогресу черги.
2. «Змінити чергу» → знайти деталь → вибрати конкретні копії → прибрати. Лічильник надрукованого не збільшується. Прибирання останньої копії спорожнює чергу.
3. «Скасувати чергу» показує підтвердження; відмова зберігає її, підтвердження прибирає.
4. Максимум — 200 невиконаних копій, партія — до 20. Сума активної черги та нового вибору понад 200 блокує додавання з поясненням. Після підтвердження частини звільняється місце для нових копій; історичний total може бути більшим за 200.
5. Перемкнути режим на місця зберігання та назад: черги незалежні.

## Власник і конкурентні зміни

1. Права `parts.view` + `stickers.manage` потрібні, як і раніше. Після втрати права друк і зміна черги заблоковані; актуальні права перевіряються перед дією та після асинхронного підготування.
2. Вихід або зміна бізнесу очищають відповідні черги та старий вибір; дані не переносяться в іншого користувача чи бізнес.
3. У двох вкладках змінити чергу, поки в першій відкривається друк або підтвердження. Застаріла дія не змінює новий стан. Web Locks серіалізують кооперативні зміни; без них порівняння збереженого envelope захищає від уже записаних чужих змін, але localStorage не гарантує атомарності одночасних записів.
4. За забороненого localStorage черга працює в пам'яті з повідомленням про неможливість відновлення після закриття.
5. Строк збереження — 24 години після останньої зміни. Друк/PDF/завантаження/поширення без підтвердження не оновлюють прогрес.

## Виконана перевірка

На базі `7c07c9d` із цією реалізацією: `npm run check` PASS (2375 unit + 271 contract + 50 integration = 2696 тестів), `npm run build:qa` PASS. Цільовий набір стікерів: 116 тестів, включно з наявною чергою місць зберігання та новими сценаріями копій. Реальний генератор сформував 20 елементів стікерів у HTML у сценарії 25 → 20 → підтвердження 7 → залишок 18 після remount. Окреме read-only code review не знайшло зауважень у batching, persistence, ownership, stale output і permission guards.

HTTP-перевірка модуля Vite підтвердила, що localhost:5173 віддає оновлений екран запчастин із чергою. Авторизований UI, браузерний print preview, фізичний принтер і сканування паперу після цієї зміни не перевірялися — ручний флоу вище виконує користувач. Старі браузерні результати не є доказом нової поведінки.
